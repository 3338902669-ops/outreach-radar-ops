# Outreach Radar Ops

> 把「给陌生客户发信」从手工活儿，变成**有闸门、有追踪、有判决、可复算**的生产系统。

一套可直接被 agent 加载执行的技能包。**方法完整保留，数据全部脱敏。**

---

## 这个包解决什么问题

绝大多数外联系统失败，不是因为发得不够多，而是因为**发出去的东西没人能证明它是对的**。

这个包给出的答案是三条：

1. **每条规则都来自一次真实事故** —— 规则不是拍脑袋定的，是踩出来的；
2. **闸门 fail-closed** —— 拦不住就不发，没有"这次特殊"的开关；
3. **一次运行给一条判决** —— 可机器读取，可独立复算。

1. 先读 `SKILL.md` 第 0 节「这套东西的立场」——如果不认同那个立场，后面都不用看了。

## 你能从中学到什么（如果你在做别的批量业务）

这套架构是**领域无关**的。把「写信」换成「生成报告」「发布内容」「批量改配置」，结构完全一样：

- **分界线**：生成与执行分离，生成器永不执行，执行器永不生成。
- **双闸门**：不同语义的批次用不同的闸，用错会整批假 FAIL。
- **内容闸**：把"输出里说的话"变成可核验断言，逐条回一手来源比对。
- **判决**：一个脚本、一行 JSON、一个退出码。
- **口径**：真实值要打折（代理预取 / 重复计数 / 缓存命中），不能直接上报原始数。

## 脱敏声明

本包由真实生产系统的操作规范改写而成。已移除：

- 全部品牌名、域名、邮箱、收件人姓名与联系方式
- 全部服务商名称与账号信息
- 全部本机路径、凭据与密钥

保留的是**方法论、架构、闸门语义、不变量清单与事故类型**——这些才是价值所在。

> 一句话：**它教的不是"我用了什么工具"，而是"我如何保证每一次发送都是可证明的"。**
