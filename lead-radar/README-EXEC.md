# 可执行获客雷达（run.mjs）

> 2026-10-08 由 **dsh** 重建。取代原先只能跑在 Hatch DSL 运行时里的 `lead-radar.js`。

## 为什么重建

旧的 `lead-radar.js` 有两个问题：
1. **不可独立执行**：`node --check` 通过，但它依赖运行时注入的 `phase()/agent()/parallel()/args`，直接 `node lead-radar.js` 会 `ReferenceError`。
2. **产不出可投商机**：2026-10-06 / 10-07 两轮简报共 12 条，逐条核验后**可执行 0 条**（2 条 404、2 条是分类页、3 条已关闭/过期、其余全职岗）。原因是没有可用性闸，且 15 个源里混着 3 个全职招聘板。

## 怎么跑

```bash
cd lead-radar
node run.mjs                 # 正常跑：抓取 + HTTP 可用性闸 + 出简报
node run.mjs --dry-run       # 只做结构化筛选，不发 HTTP
node run.mjs --source=freelancer
node run.mjs --check-top=40  # 限制 HTTP 复核条数（默认 12）
```

零依赖，Node 18+（用到内置 `fetch` / `AbortSignal.timeout`）。产物：`briefs/<日期>-可执行版.md` 与同名 `.json`。

## 它保证什么（硬门槛）

1. **只扫接单/众包源**；全职招聘板默认不进正文（`sources.json` 的 `group` 字段区分）。
2. 每条候选必须过**可用性闸**（`lib-gate.mjs`）：HTTP 状态、正文关闭/过期标记（closed/expired/awarded…）、形态判定、正文长度。
3. **正文只放通过项**；未通过的进附录并**写明原因**，不做无理由丢弃。
4. 每条必带：真项目页 URL、发布时间、核验时间、HTTP 状态、**评分依据**（可复核的加分/扣分项）。
5. 输出**分源计数表**（含 0 条与失败原因），不让「覆盖 N 个来源」变成空话。
6. 脚本**不自动投标、不自动联系任何人**（平台条款禁止）。投递必须由本人账号手动完成。

## 评分口径（可复核，不是胜率预测）

- 技能匹配 +3 / 爬虫自动化 +2
- 预算按**区间中点换算 USD** 分档：≥$2000 +3、≥$750 +2、≥$250 +1（**必须换算**，否则 INR 12500 会被当成 12500 美元）
- 有发布时间 +1
- 投标数 ≤5 +1；>20 −1；>50 −2（几无胜算）

## 已知限制（如实声明）

1. HTTP 复核条数受 `--check-top` 限制；超出部分标注「未做 HTTP 核验」，不得当作已核验。
2. 汇率是粗表（`FX_TO_USD`），只用于跨币种**可比性**，**不可用于报价**。
3. 电鸭适配器依赖其页面结构；结构变化时会返回 0 条而非报错——分源计数表会暴露这一点。
4. 技能匹配用正则白/黑名单（`WEB_JOBS` / `NOT_WEB`），会有漏报与误报；误报会体现在评分与摘要里，请人工过目。
5. 抓取频率：每源 1 请求/次，请勿高频重跑。

## 文件

- `run.mjs` — 主程序（可执行）
- `lib-gate.mjs` — 可用性闸 + 评分
- `lib-adapters.mjs` — 各源适配器（无凭据、公开可抓的部分）
- `sources.json` — 源注册表（分组 / 是否启用 / 未启用原因）
- `lead-radar.js` — **旧版 DSL 脚本，保留作历史参照，不再是执行入口**
## 两条「不用把平台密码交给程序」的渠道（2026-10-08 新增）

### A. 手动 URL 清单（零配置，立即可用）

```bash
node run.mjs --urls=list.txt          # 一行一个 URL，可写 "URL<TAB>标题"，# 开头为注释
```

你在任何平台（含需登录的 Upwork/Guru）看到中意的项目，把链接粘进 `list.txt` 即可跑闸出简报。

### B. 职位提醒邮件（推荐用于低竞争平台）

Upwork / Guru / Contra 的条款禁止自动抓取与自动投标，**账号封禁风险高**——所以本脚本**不登录、不抓取**这些平台。
但这些平台会主动把新职位提醒**发到你的邮箱**，那是发给你的数据：

1. 在平台里开启职位提醒（关键词建议：`website` `wordpress` `webflow` `react` `landing page` `web scraping` `automation`）。
2. 把提醒邮件导出成 `.eml`（或直接转发保存为 `.txt`），放进一个目录。
3. 设环境变量并开启该源：

```bash
set RADAR_MAIL_DIR_UPWORK=D:\radar-mail\upwork
node run.mjs --source=upwork-alerts
```

### ⚠️ 必须知道的一件事：这些页面**匿名访问是 403**

实测（2026-10-08，E1）：`upwork.com/jobs/...` 与 `guru.com/jobs/...` 对无登录请求一律返回 **HTTP 403**（Cloudflare 反爬）。
因此本脚本**无法独立核验**这类页面（预算/时效/是否已关闭）。处理方式：

- 401/403/429/999 被识别为 `login_wall`，**不再当作死链**（否则会误杀整条合法渠道）；
- 但这类条目**绝不混进「可投清单」**，一律进 **「待人工确认」** 区，并明确标注「未独立核验」；
- 你登录后人工确认预算与时效，再决定投不投。

**这是刻意的取舍：宁可少给几条，也不把没核验过的东西说成已核验。**
