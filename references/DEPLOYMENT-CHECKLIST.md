# Deployment Checklist — 上线与值守检查单

> 这份清单里每一条都对应一次真实故障。上线前逐条过，值守时定期复查。

---

## A. 调度器（最高频的静默故障源）

- [ ] **电源条件**：任务是否勾选了"使用电池时不启动"？
      → 真实故障：20 个任务**静默不跑** —— 返回码 0、状态"就绪"、**日志一行不写**。症状是"定时节奏凭空消失"。
- [ ] **触发方式**：单次运行，**不是**短间隔触发无限循环。
- [ ] **失败重启**：失败后是否重试、重试几次、退避多少。
- [ ] **最高权限**：需要访问网络 / 写文件的任务是否具备。
- [ ] **防重入**：任务本身有没有锁？锁在持有者存活时是否正确跳过？
- [ ] **验证"真的跑了"**：不只看任务状态，要看**它写没写日志**。

---

## B. 防重入锁

- [ ] 无锁 → **拒绝启动**（不要"善意地先跑一轮"）。
- [ ] 持有者进程存活 → **跳过**。
- [ ] **禁止**用"锁龄小于 N 分钟"作为跳过条件 —— 慢运行必然导致并发。
- [ ] 持有者已死 / 锁龄超长且 PID 无法确认 → 允许接管，并写告警。
- [ ] 锁文件损坏 → 当作"无法确认"，**拒绝**而不是放行。

---

## C. 投递安全

- [ ] 演练环境**硬锁探测模式**（改代码，不是加参数）。
- [ ] 发送器里的目录路径**不得写死**为生产目录。
- [ ] 时间窗校验是**投递前自跑项**，不是"上次设过"。
- [ ] 幂等：同一批信重复投递不会重复发送。
- [ ] 投递成功**必须记账**（哪个账本、什么格式、谁能读）。

---

## D. 账本与产物

- [ ] 每一个事实**只有一个权威账本**。
- [ ] 不可逆记录（抑制、退订）**只追加，不重写**。
- [ ] 读 JSON 一律**剥 BOM**（否则解析抛错，会被误判成"账本损坏"）。
- [ ] 汇报只读权威账本，**不读"看起来最新"的临时产物**。
- [ ] 禁止任何 **stale 回退**：某一步失败就失败，不要回退去读磁盘上"最新的"旧产物 —— 那等于把失败伪装成成功。

---

## E. 部署

- [ ] **部署树纯度**：半成品绝不落在部署目录里（一次部署命令就会把它推上线）。
- [ ] 部署是**整份快照**还是增量？如果是快照，**只传部分文件会删掉其余文件**。
- [ ] 部署前确认线上内容与本地基线**逐字节一致**（哈希比对），不要凭"看起来一样"。
- [ ] 有**预览环境**可先验证？先预览、再生产。
- [ ] 回滚方案写下来（改哪几处、怎么退）。

---

## F. 值守

- [ ] 体检脚本定期运行，结果写进**值守日志**。
- [ ] 体检项至少覆盖：队列到点未发数 / 闸门挂起数 / 锁卫生 / 账本可读性 / 不变量判决。
- [ ] 体检失败**要有告警落盘**（文件或消息），不能只打印。
- [ ] 告警必须能被**进程外**的东西看到 —— 如果值班 agent 与主程序同生共死，它挂了就没人告警。

---

## G. 权限与安全

- [ ] 凭据只放环境变量或受管凭据，**明示 agent 禁止打印**。
- [ ] 遮蔽作用于**即将回显 / 落盘的整行**，而不只是命令输出。
- [ ] 最小权限：能只读就不用可写。
- [ ] 不可逆动作（发送 / 发布 / 删除）**必须人工确认**。
- [ ] **授权 ≠ 跳过门禁**：批准解除的是"问不问"，不是"查不查"。

---

## H. 上线前的最后四问

1. **它会怎么失败？**（有哪一个夹具证明过闸门会红？）
2. **我怎么知道它现在好不好？**（一条命令、一行 JSON 能回答吗？）
3. **错了怎么退？**（回滚步骤写在哪？）
4. **谁在看它？**（值班机制在进程内还是进程外？）

> 四个问题答不上来任何一个，就不要开真发。
